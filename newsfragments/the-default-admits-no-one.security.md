An API endpoint that declares no `auth=`, under a router that declares none either, now refuses every caller: 401 for anonymous, 403 for everyone else. Before, it admitted any logged-in user and any unrestricted token without asking anything of the person, so an app whose endpoints were not yet annotated let any logged-in user read and change its data unless the endpoint checked permissions itself. Such endpoints stop answering until they declare `auth=guarded(...)`, `scoped(...)` or `authenticated()`. `/api/ping/` now admits any valid credential, scoped ones included, so adding a remote with a narrowed token no longer fails as "Authentication failed".
