An outside client asks the authorization server for **bundles**, never permission codenames: one `<app>:read` / `<app>:write` pair per phoxtail app, derived from the codenames the app's endpoints and tools already name (write includes read), so a renamed model changes no issued credential's meaning and a new door joins its bundle by existing. The discovery document and the MCP server's protected-resource document both list every bundle; a request for anything else — the library's placeholder `read`, a codename, or nothing at all — is refused as `invalid_scope`, and a client that asks for nothing gets nothing rather than everything. The consent screen is now phoxtail's: it names the client by the host of its metadata URL when it has one (its self-declared name otherwise), names the host the browser will be sent to, says so when that is this device, and lists what the client would be able to do. Approving the requested set whole; per-bundle choice is not offered yet. The system check `E004` fails startup if a project's own `OAUTH2_PROVIDER` displaces the scope backend or the validator.
