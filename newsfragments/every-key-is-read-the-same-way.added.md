The API now reads a key the authorization server issued after a person's consent, so a client holding one can act — within the bundles approved and the person's own permissions. One `Authorization: Bearer` header is routed by the key's shape to one table (phoxtail's own keys carry the `phxt_` prefix; the server's cannot), and either kind is read into one credential: the names it carries as stored, and the codenames those names mean today. Bundles are now valid on phoxtail's own keys too — `cms:read` beside a codename in the admin or the CLI — so a personal key gains the same protection against a model rename. `/api/whoami/` reports `bundles` beside `scopes`, `phoxtail_whoami` repeats it, and the refusal an unannotated endpoint gives a narrowed key now says the endpoint has not named its permission instead of advising a kind of key the holder may not be able to have. A key bound to the MCP server's address is refused at the API until the API can say it stands behind that server.
