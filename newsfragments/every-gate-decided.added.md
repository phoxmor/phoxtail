Every RFC 9700 gate the authorization server library defines is now decided: nine are on from the first day — the four added here refuse a key sent in the query string and make replay protection, exact redirect matching and required PKCE deploy-check errors rather than warnings — and one is kept off with its reason written down: a plaintext redirect scheme must stay allowed for a program listening on its own machine, whose callback is `http://localhost`, and that is every CLI client. The rule the standard actually states, plaintext only to loopback, is enforced instead: an `http` redirect to any other host is refused at the authorization endpoint whatever a client registered. `E007` fails startup if the kept gate is turned on or `http` is dropped, and a test fails if a future library release adds a gate nobody has decided.
