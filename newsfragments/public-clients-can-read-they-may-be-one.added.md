The authorization server's discovery document now lists `none` among its token-endpoint authentication methods — a phone app or a CLI has no secret to present and proves itself with PKCE instead, which the server already accepted but did not advertise — and a client listening on `http://localhost:<any port>` for its callback is recognised as the client that registered `http://localhost:<some port>`, as RFC 8252 allows for loopback addresses. Every authorization response now carries the `iss` parameter (RFC 9207), so a client talking to several authorization servers can tell which one answered.
