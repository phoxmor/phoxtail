The MCP server is deployed in production too, as `mcp.<domain>`: the `mcp` service joins the production compose (no published port; nginx reaches it by service name), `phoxtail nginx create production` writes a server block for it that passes the request through exactly as sent — same host, same path, no redirect to the site's origin, since every trust rule the connector is built on is keyed on that name — and `phoxtail ssl obtain` and `phoxtail server ssl` name it on the site's certificate (`--expand`, so an existing certificate grows; `server ssl` treats a certificate that lacks the name as absent and checks the record resolves). The two endpoints anyone may call before logging in, `/o/register/` and `/o/authorize/`, are rate-limited per client address at the edge (ten a minute, burst twenty, `429`); the token endpoint and the MCP server are not. `phoxtail env create production` now lists `web` in `ALLOWED_HOSTS` beside the domain, because the MCP server asks the API who a caller is at `http://web` inside the compose network. Already-deployed projects need `web` added to `ALLOWED_HOSTS` by hand, the DNS record for `mcp.<domain>`, a regenerated `nginx.conf`, the certificate obtained again, and both containers restarted.
